Kerberos machine principals that may authenticate to Jenkins, one pattern per line. Machines are principals of the form host/fqdn@REALM (a Unix host keytab) or NAME$@REALM (a Windows computer account). Leave empty to keep the default, where machine principals are treated as unknown users and proceed anonymously.

Patterns are matched case-insensitively against the whole principal, realm included, with * as the only wildcard: host/*.example.com@EXAMPLE.COM, *$@EXAMPLE.COM. Every pattern must name a realm. Prefix a pattern with ! to deny it; a deny entry always wins, so !stolen-laptop$@EXAMPLE.COM revokes one machine admitted by a broader glob.

An admitted machine authenticates as its lowercased principal, for example host/agent01.example.com@example.com, and belongs to exactly one group, kerberos-machines. It does not belong to authenticated and has no permissions until you grant some, to that group or to the machine's name, in your authorization strategy. No Jenkins user record is created for it.

Treat these identities as low trust: any local administrator on a domain-joined host holds that host's ticket. Grant the minimum the automation needs.
